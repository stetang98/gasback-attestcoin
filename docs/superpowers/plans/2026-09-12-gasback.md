# GasBack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver a truthful, competitive BUIDL CTC entry today with a real proof-authorized failed-transaction rebate.

**Architecture:** Independent Solidity package under `chain/`; owner-authored static browser application under `web/`; public evidence exported from deployment/proof scripts. Creditcoin state is authoritative and the UI never fabricates a claim.

**Tech Stack:** Solidity 0.8.28 or compatible newer version, ethers 6, @gluwa/usc-sdk 0.18.0, local EVM tests, static TypeScript/HTML frontend, Sites hosting.

**Spec:** docs/superpowers/specs/2026-09-12-gasback-design.md

### Task 1: Proof-bound rebate contract and adversarial tests

**Files:** `chain/package.json`, `chain/contracts/GasBackVault.sol`, `chain/contracts/DemoAction.sol`, `chain/test/gasback.test.cjs`, `chain/scripts/compile.cjs`, `chain/artifacts/*.json`.

**Interfaces:** Export artifact ABI/bytecode for `GasBackVault` and `DemoAction`. The vault has a fixed native verifier, owner-funded budget, immutable preauthorized ticket fields, one-time claim, and replay prevention. Send root the exact final ABI before integration scripts are written.

Ticket fields: beneficiary, sourceSender, sourceTarget, sourceNonce, minSourceBlock, maxSourceBlock, claimDeadline, minGasLimit, rebate, calldataHash. Chain key 1 is fixed. Enforce expiry on Creditcoin and source block range through verifier-bound headerNumber. Bind beneficiary to sourceSender for this MVP. Nullifier is based on verified source identity, never a caller-supplied txHash. Only supported type-2 source transactions are accepted and unsupported encodings fail closed.

- [ ] Write failing real-EVM tests for an eligible failed transaction and each disallowed case.
- [ ] Assert the intended missing behavior fails before implementing production contract logic.
- [ ] Implement source success/revert actions and proof-first claim validation.
- [ ] Verify success receipt rejected, tampered proof rejected, wrong sender/target/calldata/nonce/chain rejected, outside source range rejected, expired ticket rejected, replay rejected, and fund shortage/reentrancy leave consistent state.
- [ ] Compile and run tests, recording commands and counts in the task report; commit only `chain/`.

Canonical expected test behaviors:

```js
assert.equal(await vault.claimed(ticketId), false);
await claimVerifiedFailure();
assert.equal(await vault.claimed(ticketId), true);
await assert.rejects(claimVerifiedFailure());
await assert.rejects(claimWithSuccessfulReceipt());
await assert.rejects(claimWithTamperedPayload());
```

Tests use a local verifier harness only to isolate policy logic; the live proof/precompile check remains a separate required integration test.
